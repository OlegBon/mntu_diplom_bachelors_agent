# 154 — Якість експертних текстових висновків

## Мета

Допомогти експерту й admin бачити проблеми заповнення полів «Метод
ідентифікації», «Висновок щодо ідентифікації» та «Коментар експерта», не
підміняючи експертний висновок автоматичним судженням.

## Погоджений підхід

- Перший етап — explainable quality checks: порожній/надто короткий текст,
  placeholder, надмірне повторення, незвично великий текст, необов'язкові
  поля та зв'язок із selected identification status. Це warning, не блокування
  і не зміна даних.
- Окремо додати metadata-only operational statistics за кожним полем, а не
  один змішаний «score»: кількість непорожніх значень, median/average слів і
  символів без пробілів, а також три найкоротші й три найдовші поточні значення
  з посиланням лише на `report_id` і датою. Поля: метод ідентифікації,
  висновок щодо ідентифікації, коментар експерта та коментар до зміни статусу.
  Довжина не означає якість, тому UI не створює норму, рейтинг або penalty.
- Text metrics показуються лише адміністратору; в analytics не виводяться
  самі тексти або уривки. Для україномовного й англомовного введення потрібне
  одне Unicode-aware правило підрахунку слів. Потрібно окремо визначити,
  чи зріз бере поточне значення report, чи append-only snapshot: чинна історія
  не повинна видаватися за historical text provenance без відповідних даних.
- «Тональність» не є корисною первинною метрикою для професійного висновку.
  До неї можна повернутися лише після визначення rubric, labelled corpus і
  користувацької цінності. Не робити висновків «правда/неправда» чи quality
  експерта з одного тексту.
- Якщо пізніше використовувати NLP/ML: спершу 151-подібний data contract,
  consent/privacy, human labels, evaluation by Ukrainian and English text,
  versioning та human review. Не надсилати приватні тексти до зовнішнього LLM
  без окремої письмової політики й дозволу.
- Результати private; не потрапляють у публічний паспорт, PDF або rating
  експертів.

## Залежності

Перші rules-based checks можуть бути окремою малою задачею. Будь-який NLP/ML
експеримент залежить від 151.
