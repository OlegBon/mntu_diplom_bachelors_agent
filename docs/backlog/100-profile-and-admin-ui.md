# Профіль і адміністративний інтерфейс

## Мета

Завершити робочий контур користувача та адміністратора без передчасної
реалізації ML-аналітики.

## Scope

- Профіль поточного користувача: зміна лише імені/прізвища/по батькові та
  пароля з перевіркою поточного пароля. Username і роль не змінюються з
  профілю.
- Admin UI для створення, редагування ролей і **деактивації** експертів.
  Hard delete не застосовується, бо експерт пов’язаний зі звітами й audit
  history; self-deactivate та деактивація останнього active admin заборонені.
- Read-only перегляд server-side довідників. Редагування довідників,
  версіонування, причина, джерельний документ та дія лише для нових звітів
  винесені у [105](./105-versioned-reference-catalogs.md). Інтерфейс
  ринкових даних залежить від [110](./110-authoritative-market-data-and-fx.md).
- Виділити місце для майбутньої аналітики без показу демо-ML як фактів.
- `/statistics/expert-performance` і UI реальної статистики не входять у
  задачу: виправлення контракту, RBAC і regression-тести винесені у
  [108](./108-expert-statistics-and-analytics-contract.md).

## Критерії готовності

- Небезпечні admin-дії доступні тільки admin і мають зрозумілий UI-стан.
- Деактивація не руйнує зв’язки зі звітами, подіями та паспортами.
- Довідники відображаються з API; frontend не зберігає їх дублікати та не
  створює фальшивий editor до реалізації 105.
