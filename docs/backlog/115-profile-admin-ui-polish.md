# 115 — UI-polish профілю та адміністративних екранів

## Мета

Окремо узгодити й виконати дрібні візуальні та responsive-покращення після
ручного використання Profile, «Експертів», «Довідників» і пов’язаних форм.

## Межі

- Відступи, типографіка, ширини контролів, вирівнювання та responsive-layout.
- Зрозумілі UI-стани кнопок, таблиць, карток і модалок.
- Доступність: focus-visible, контраст, підписи та keyboard-навігація.
- Спільні SCSS primitives замість точкових стилів у `dist`.

## Поза межами

- Зміна ролей, RBAC, API-контрактів або структури БД.
- Версіонування правил IDC та довідників: базовий механізм уже реалізовано; зміни методики плануються окремим ruleset-зрізом, не в межах UI-polish.
- Статистика/аналітика вже реалізована у 108; її наступний active-time і
  period-filters зріз винесено у [112](./112-expert-active-time-and-analytics-periods.md).

## Відкриті рішення

- Зібрати конкретні спостереження після ручної перевірки desktop, tablet і mobile.
- Для кожної зміни визначати, чи вона є локальною, чи має перейти у загальний компонент.

## Критерії готовності

- Погоджені UI-зауваження відтворені у `frontend/src`, а не в `frontend/dist`.
- Ключові екрани перевірені на mobile, tablet і desktop.
- `npm run build`, релевантні frontend-тести й `git diff --check` успішні.
- У `docs/progress.md` зафіксовані рішення, перевірки та обмеження.
