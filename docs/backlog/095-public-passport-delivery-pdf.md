# Публічний паспорт: передача замовнику та PDF

## Мета

Завершити сценарій передачі виданого звіту замовнику: admin публікує паспорт,
отримує його непередбачуваний код, QR і посилання, а також завантажує PDF-паспорт.
Покупець відкриває поточну публічну проєкцію без входу.

## Передумови

- 090 реалізував active/revocable `public_id`, allow-listed anonymous endpoint і SVG QR.
- У QR кодується повний URL `passport.html?id=<public_id>`; `DR-…` лишається
  внутрішнім послідовним номером звіту й не є ключем публічного доступу.
- Публічна проєкція вже виключає ціну, коментарі, експерта, комерційний стан,
  історію й private media.

## Scope

- У виданому й опублікованому detail admin бачить QR, сам `public_id`, повний
  публічний URL і може скопіювати посилання або код.
- Пошук на landing приймає або окремий код, або повний валідний URL із QR і
  відкриває лише `public_id`; для `DR-…` показує зрозуміле пояснення.
- Admin завантажує server-generated PDF-паспорт лише для активного published
  issued report. PDF будується on-demand з тієї ж allow-listed public projection,
  містить номер звіту для читання, видимі характеристики, дату видачі, QR,
  публічний URL і код.
- PDF віддається з коректними `Content-Type` і `Content-Disposition`; QR у ньому
  містить лише валідний current public URL.
- Reissue негайно вимикає старий URL/QR і вимагає повторно завантажити PDF з новим
  кодом. Revoke або void забороняють нове завантаження; вже переданий файл не може
  бути фізично відкликаний, але його URL одразу повертає opaque `404`.
- Додати API/RBAC, PDF-content і frontend/E2E тести, включно з URL-vs-code lookup,
  reissue, revoke і void.

## Не входить

- Повний приватний PDF-звіт, ціна, коментарі, статус продажу, історія,
  персональні дані або private media.
- Автоматичне надсилання e-mail, зовнішнє сховище, цифровий підпис чи юридична
  сертифікація PDF.
- Публічні фото/plotting: це окреме рішення у 130.
- Persisted PDF snapshots або версії документа. Початковий варіант генерує файл
  на запит; незмінний юридичний snapshot потребуватиме окремого рішення.

## Відкриті рішення перед реалізацією

- Назва документа для користувача: «Публічний паспорт» чи «PDF-паспорт звіту».
- Який server-side PDF renderer і шрифт підтримують український текст без
  зовнішнього сервісу.
- Від якого production public origin формувати URL у PDF; локальний `localhost`
  не може бути значенням для переданого замовнику документа.
- Чи потрібні в PDF дата публікації, дата генерації та попередження про відкликання.

## Критерії готовності

- Публічний код не можна вгадати з номера звіту, але його зручно скопіювати,
  передати та вставити як код або URL.
- PDF і браузерна сторінка відображають однаковий дозволений набір даних.
- Ні PDF, ні QR, ні lookup не розкривають private endpoint або чутливі поля.
- Reissue/revoke/void перевірені автоматично й вручну на виданому звіті.
