# Майстер створення звіту

## Мета

Створити послідовний майстер, що дозволяє експерту сформувати та зберегти
чернетку звіту без підміни експертних висновків автоматичними розрахунками.

## Scope

- Рівно три responsive-кроки: ідентифікація/4C, геометрія/IDC, висновок/медіа.
- Окреме редаговане поле фактичної дати дослідження / оцінки; дата створення не є його заміною.
- Preview наступного номера не резервує ID; остаточний номер призначає `POST /reports`.
- Довідники форми та grade mappings завантажуються з API/БД, не hardcode з frontend.
- Нова чернетка має `market_status=not_for_sale`; комерційний стан переноситься до 080 detail/edit.
- Live IDC-розрахунок як preview; backend — єдине джерело істини під час save.
- Явне маркування введених, розрахованих та експертно підтверджених даних.
- Необов'язкові приватні вкладення завантажуються після створення `draft` через
  `media_assets`; вони не потрібні для першого збереження.

## Реалізовано, очікує ручної перевірки

- Alembic revision `0004_report_wizard`: поле `examination_date` та довідники
  `girdle_thickness` / `culet_size`.
- `GET /reports/next-id`, `POST /reports/preview`, `POST /reports` і
  `GET /reference-values`; усі авторитетні значення походять із API/БД.
- Три кроки, native-валідація, server-side live preview IDC та детермінований
  демонстраційний прогноз `USD … d`. Він не зберігається як ціна звіту і не є
  ринковою, експертною або продажною ціною.
- Browser E2E з mock HTTP проходить повний шлях створення draft без зміни
  MariaDB.

## Ручна перевірка перед закриттям

1. Увійти як `gemologist`, заповнити обов'язкові поля трьох кроків і зберегти
   чернетку без медіа.
2. Переконатися у redirect на dashboard, появі нового `draft` та наступному
   preview номера після повторного відкриття майстра.
3. Медіа, detail/edit, комерційний статус і transitions не входять до цього
   ручного сценарію; вони належать відповідно 050 та 080.

## Критерії готовності

- Чернетка не стає виданим звітом випадково.
- Помилки валідації зрозумілі поруч із відповідними полями.
- Є критичні нові API, JS/DOM і E2E-перевірки без зміни наявних тестів без
  окремого погодження.
