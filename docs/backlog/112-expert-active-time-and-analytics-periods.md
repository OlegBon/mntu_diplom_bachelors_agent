# Активний час експерта та періоди аналітики

## Мета

Додати достовірний облік саме активного часу роботи над звітом і часові
фільтри для operational analytics, не підміняючи їх різницею між датами
створення, збереження чи рішення admin.

## Передумови

У 108 реалізовано status-зріз експертів і тривалість review-циклу
адміністратора. Це різні метрики: review-cycle вимірюється з audit events,
а активний час заповнення експертом зараз не фіксується. Старе
`evaluation_time_sec` не є надійним джерелом для поточного wizard.

## Scope

- Узгодити події start / pause / resume / save / finish для сесії роботи над
  чернеткою, її ownership і правила одночасних вкладок.
- Не рахувати неактивну вкладку, розрив сесії або просто відкриту сторінку як
  робочий час; описати offline/перезапуск браузера.
- Зберігати append-only факти або достатній audit trail, щоб агрегати можна
  було перерахувати й пояснити.
- Додати admin-only API і вкладку «Експерти» з обраним періодом, середньою,
  медіанною, трьома найкоротшими та трьома найдовшими фактичними сесіями з
  посиланнями на report ID.
- Додати періодні фільтри для вже наявних status-агрегатів і review-циклів,
  чітко визначивши поле дати для кожної метрики.

## Не входить

- Кадровий рейтинг, автоматичні висновки про продуктивність чи прихована
  telemetry.
- Відновлення історичного active-time для старих звітів із приблизних дат.

## Критерії готовності

- Один сценарій у кількох вкладках не подвоює активний час.
- API документує джерело й межі кожної часової метрики, а UI не називає
  review-cycle «часом роботи».
- Є unit/API та browser-перевірка start/pause/resume і вибраного періоду.
