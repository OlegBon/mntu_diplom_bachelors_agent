# 131 — Зображення у PDF публічного паспорта

## Мета

Додати до on-demand PDF публічного паспорта фотографію каменю та/або схему
огранювання, якщо їх явно опублікував admin для поточного виданого звіту.

## Передумови

- 130 вже дозволяє admin публікувати лише `stone_photo` і `plotting_diagram`
  з JPEG/PNG/WebP для `issued` report.
- Public HTML показує allow-listed media лише за чинним public token.
- Поточний PDF навмисно не містить вкладень; 131 змінює саме це обмеження.

## Scope

- Передавати в PDF-генератор лише поточний allow-listed набір public media,
  без filename, storage key чи інших private metadata у публічному документі.
- Додати наприкінці PDF секцію «Зображення каменю» з читабельними підписами
  «Фото каменю» та «Схема огранювання».
- Безпечно завантажувати й декодувати лише JPEG/PNG/WebP, повторно звіряючи
  public eligibility, активність паспорта та checksum так само, як public
  content endpoint.
- Визначити сталі межі: максимальний розмір на сторінці, пропорційне
  масштабування, pagination, відсутність зображень і пошкоджений файл.
- Додати API/PDF-тести: public media присутнє, private/revoked/void/tampered
  media не потрапляє, PDF лишається доступним без медіа.
- Оновити `architecture`, domain workflow, db/PDF docs, work plan та progress.

## Поза межами

- Private `instrument_image`, `supporting_document` та будь-які нові типи media.
- Вбудовування ринкових цін, коментарів експерта чи іншого private контенту.
- Зберігання PDF як snapshot-а, зовнішній CDN або зміна public token/RBAC.

## Критерії готовності

- PDF показує лише явно опубліковані зображення активного паспорта.
- Порядок стабільний: фото каменю, потім схема огранювання; за відсутності
  файлу секція не створюється.
- Файл коректно розміщений на A4 без виходу за межі, незалежно від пропорцій.
- Revoke, reissue, void і SHA-256 mismatch не відкривають media через PDF.
- Документація чітко відрізняє public PDF від private attachments.
