# Ядро звіту та довідкові дані

## Мета

Реалізувати узгоджену модель звіту, його статуси, дані каменю та серверні
довідники як основу для dashboard, майстра й паспорта.

Фінансові поля та межі demo-прогнозу реалізовуються за
[ADR-002](../decisions/002-financial-calculation-contract.md): поточний `price`
не переноситься автоматично, а нові суми потребують окремих `Decimal`/`Numeric`
контрактів, тестів і погодженої Alembic-міграції.

## Scope

- Статуси, автор, експерт-видавець, дата створення/видачі й журнал подій.
- Поля 4C, форма, виміри, fluorescence, girdle, culet, proportions, symmetry
  і polish з чіткими одиницями та валідацією.
- Окремі `origin`, `treatment_status`, `identification_status`.
- Вирівняти ORM, Pydantic, CRUD, API та `diamond_market`-довідники.
- Позначити розраховані значення й експертно підтверджені значення окремо.
- Додати окремі фінансові сутності або поля лише за контрактом ADR-002; не
  трактувати legacy `price` як оцінку чи продаж.

## Не входить

- Повна IDC-автоматизація без погоджених правил, додаткових параметрів і
  експертної методики.
- ML-прогноз або публічний UI.

## Критерії готовності

- Стани й переходи захищені RBAC.
- Нові API-контракти мають важливі integration-перевірки.
- Зміни схеми виконані лише версіонованими міграціями.
