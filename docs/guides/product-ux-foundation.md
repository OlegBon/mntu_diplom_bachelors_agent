# UX-основа продукту

Цей документ фіксує погоджений напрям UX для Diamant ID до реалізації
окремих функціональних зрізів звіту, паспорта, профілю та admin-панелі.

## Навігація

На desktop логотип Diamant ID розташований ліворуч. Усі навігаційні пункти
розташовуються праворуч, перед профілем і дією виходу. На ширині до `900px`
основна навігація відкривається burger-кнопкою.

| Стан | Меню |
| --- | --- |
| Гість | `Головна`, `Перевірити паспорт`, `Увійти` |
| Gemologist | `Звіти`, `Новий звіт`, `Аналітика`, профіль, `Вийти` |
| Admin | Меню gemologist; окремі admin-розділи з’являться лише в задачі profile/admin UI |

Frontend може покращувати орієнтацію, але не є джерелом істини для ролей:
backend зберігає остаточну перевірку доступу.

## Ключові поверхні

- **Головна:** перевірка публічного паспорта та перехід до входу. Одне
  предметне фото каменю пояснює домен, але не імітує сертифікат або результат
  оцінки.
- **Dashboard:** table-first список звітів; пошук, фільтри й пагінація не
  замінюються декоративними картками.
- **Новий звіт:** покрокова форма ліворуч і live-розрахунок праворуч на
  desktop. Розрахунок явно позначений як попередній до підтвердження експерта.

## Стани інтерфейсу

| Стан | Поведінка |
| --- | --- |
| Loading | Нейтральне текстове повідомлення в області даних; керування не дублює запит. |
| Empty | Пояснення відсутності результатів і доступна наступна дія. |
| Error | Людське повідомлення без технічних деталей; за можливості — повторити дію. |
| Success | Видиме підтвердження разом зі зміною даних або переходом до результату. |
| Forbidden | Пояснення, що дія недоступна, без розкриття внутрішніх даних. |

Ці стани взаємовиключні: наприклад, empty-state не показується поруч із
заповненою таблицею.

## Візуальні правила

- Основна поверхня — true white; допоміжні поверхні — дуже світлий холодний
  синій; єдиний головний акцент — сапфіровий `#2563EB`.
- Не застосовуються градієнти, фіолетові акценти, glassmorphism, вигадані
  метрики або декоративні AI-елементи.
- Всі критичні дії мають текстові підписи. Іконки лише уточнюють знайому дію
  та не замінюють зміст.
- На mobile hero, пошук і фільтри стають одноколонковими; sticky-калькулятор
  перетворюється на звичайний блок у потоці.
