# Design System: Diamant ID

> Актуальна UX-основа: [product-ux-foundation.md](./docs/guides/product-ux-foundation.md).
> На desktop навігація розташовується праворуч від логотипу, перед профілем і виходом.

Цей документ визначає принципи дизайну та компоненти для **Diamant ID** — системи ідентифікації й оцінювання діамантів. Він спирається на наявний Gulp/Pug/SCSS frontend і є єдиним джерелом візуальних правил.

## Design Philosophy (філософія дизайну)

- **Довіра до даних:** параметри каменю, оцінки та ціна подаються точно, послідовно й без декоративного шуму.
- **Робоча ефективність:** інтерфейс експерта підтримує швидке введення, перевірку та пошук звітів.
- **Зрозумілий стан:** дії, валідація, завантаження та помилки мають негайний і доступний зворотний зв’язок.
- **Адаптивність:** ключові сценарії працюють на desktop, tablet і mobile без втрати даних чи керування.

---

## Layout (макет)

- **Контейнер:** `1200px` із бічними відступами `1rem`.
- **Mobile:** `< 768px`; одна колонка, навігація згортається, великі таблиці мають горизонтальний scroll.
- **Tablet:** `768px–991px`; гнучка сітка та повні підписи контролів.
- **Desktop:** `≥ 992px`; dashboard використовує повну таблицю, майстер звіту — сітку `2fr / 1fr`.
- **Відступи:** базова одиниця `1rem`; між секціями зазвичай `2rem`; у картках `1rem–2rem`.

## Tokens (токени)

### Colors (кольори)

```scss
$primary-color: #2563eb;
$primary-hover: #1d4ed8;
$secondary-color: #64748b;
$bg-color: #f8fafc;
$text-color: #1e293b;
$white: #ffffff;
$border-color: #e2e8f0;
$success-color: #16a34a;
$error-color: #dc2626;
$warning-color: #d97706;
```

### Typography (типографіка)

```scss
$font-main: "Inter", system-ui, -apple-system, sans-serif;
$font-mono: ui-monospace, SFMono-Regular, Consolas, monospace;
```

Основний текст має бути читабельним; числові значення, ID звіту та розрахунки можуть використовувати моноширинний шрифт. Не передавай зміст лише кольором.

### Spacing (відступи)

Використовуй шкалу `0.25rem`, `0.5rem`, `0.75rem`, `1rem`, `1.5rem`, `2rem`. Нові довільні значення додавай лише коли вони виправдані конкретним компонентом.

## Components (компоненти)

### Buttons (кнопки)

- **Primary:** синій фон `$primary-color`, білий текст; для збереження звіту або основної дії.
- **Outline:** білий або прозорий фон, синя межа й текст; для другорядної дії.
- **Disabled:** знижена контрастність, `cursor: not-allowed`; дія не виконується.
- Розмір і текст кнопки мають пояснювати дію: «Зберегти звіт», «Увійти», «Очистити фільтри».

### Input Fields (поля введення)

- Кожне поле має видимий `label`, одиницю виміру або приклад там, де це допомагає.
- Звичайний стан: білий фон і `$border-color`; focus: `$primary-color` плюс видимий outline.
- Помилка: `$error-color` і текстова причина поруч із полем.
- Групуй пов’язані характеристики каменю: ідентифікація, геометрія, finish, market.

### Tables (таблиці)

Для dashboard-звітів використовується `overflow-x: auto` на малих екранах. Заголовок вирізняється фоном, числові значення вирівнюються послідовно, ID — посиланням. Не приховуй критичний статус лише за кольоровим badge.

### Filters (фільтри)

Основні фільтри залишаються видимими; розширені відкриваються окремою панеллю. Застосування й скидання мають бути явними, а поточний фільтр — зрозумілим у результатах.

### Status Badges (статуси)

Використовуй короткий текст (`Активний`, `Продано`, `Відхилено`) разом із помірним семантичним кольором. Badge не є кнопкою, якщо не має окремої дії.

### Cards (картки)

Картки мають білий або світлий фон, межу `$border-color`, радіус `8px–12px` і легку тінь. Одна картка — один пов’язаний блок даних або дії.

### Wizard and Calculator (майстер і калькулятор)

Майстер створення звіту має покрокову навігацію. Панель розрахунків sticky лише на desktop; результат Cut Grade і ціни відображається з пояснювальними назвами, не лише цифрами.

### Alerts / Toasts (сповіщення)

Повідомлення описує результат і подальшу дію. Помилка не зникає, доки користувач не може її прочитати; успіх не замінює видиму зміну даних у таблиці чи формі.

---

## Surfaces (поверхні)

- **Сторінка:** `$bg-color`.
- **Основний контент і форми:** `$white` із межею `$border-color`.
- **Вторинні панелі:** світлий фон на кшталт `#f1f5f9` або `$bg-color`.
- **Модальні вікна:** біла поверхня над затемненим overlay; Esc, close button і повернення focus обов’язкові.

---

## Imagery (зображення)

- Зображення каменю або plotting не підміняє числові параметри й має зрозумілий fallback.
- Іконки використовуються лише для підсилення знайомої дії; кнопка з іконкою без тексту має `aria-label` або еквівалентний доступний підпис.
- Декоративні зображення не повинні конкурувати з параметрами сертифіката чи калькулятором.

## Do's and Don'ts (що робити та чого не робити)

### Do's (що робити)

- Використовуй наявні SCSS-токени з `_variables.scss`.
- Перевіряй читабельність таблиць, форм і калькулятора на mobile.
- Показуй одиниці виміру, допустимі діапазони та помилки для фізичних параметрів.
- Перевіряй UI через реальну збірку Gulp і цільовий сценарій.

### Don'ts (чого не робити)

- Не редагуй `frontend/dist` вручну.
- Не додавай магічні кольори, відступи або дублікати стилів без причини.
- Не роби критичну дію лише через icon або hover.
- Не приховуй помилки валідації, auth або збереження за загальним «Щось пішло не так».

---

## Anti-Patterns (AI Slop Guardrails) / Антипатерни (настанови для запобігання AI-слопу)

- ЖОДНИХ градієнтів, glassmorphism, сяйливих сфер або декоративних тіней без функціональної причини.
- ЖОДНИХ загальних hero-секцій і маркетингових фраз замість даних про систему.
- ЖОДНИХ фальшивих графіків, метрик, оцінок каменю чи «AI insights» без реального джерела.
- ЖОДНИХ великих центрованих іконок, які не пояснюють конкретну дію.
- ЖОДНИХ надмірних scroll-анімацій; анімація має підтримувати зміну стану, а не відволікати.
- ЖОДНИХ порушень доступності заради стилю: малий контраст, focus без видимого стану, лише колір як індикатор.

## Quick Start (швидкий старт)

```scss
@use "variables";

.card {
  background: variables.$white;
  border: 1px solid variables.$border-color;
  border-radius: 8px;
  box-shadow: variables.$shadow-sm;
  padding: 1rem;
}

.btn-primary {
  background: variables.$primary-color;
  color: variables.$white;

  &:hover { background: variables.$primary-hover; }
  &:focus-visible { outline: 3px solid #93c5fd; outline-offset: 2px; }
}
```

Джерело істини для реалізації — `frontend/src/scss/_variables.scss`; після зміни Pug, SCSS або JavaScript запускай `cmd /c "cd frontend && npm run build"`.
