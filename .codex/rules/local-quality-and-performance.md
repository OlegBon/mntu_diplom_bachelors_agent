# Локальні правила: якість і продуктивність

## 1. Якість інтерфейсу

- Дотримуйся `DESIGN.md` і наявних SCSS-токенів; не додавай шаблонний UI, випадкові кольори чи дублікати компонентних стилів.
- Для кожного інтерактивного елемента передбачай доступні `:hover`, `:focus-visible`, `:active` і стан помилки, де він можливий.
- Для форм використовуй пов'язані `label`, семантичні типи полів, `autocomplete` і зрозумілі повідомлення про помилки.
- Не редагуй `frontend/dist` вручну: це результат Gulp-збірки.

## 2. Frontend-продуктивність

- Вказуй розміри або співвідношення сторін зображень, щоб уникати CLS; використовуй WebP або AVIF, якщо формат доречний.
- Зображення поза першим екраном завантажуй ліниво. Не додавай великі бібліотеки для однієї невеликої взаємодії.
- Анімуй переважно `transform` та `opacity`; не анімуй `width`, `height`, `top`, `left`, `margin` або `padding` без обґрунтування.
- Не заявляй показники Core Web Vitals без вимірювання в браузері або production-середовищі.

## 3. API і база даних

- Пагінація, фільтри та сортування мають обмежувати обсяг даних і відповідати індексам; не роби необмежених вибірок для списків.
- Не запускай довгі транзакції та не виконуй мережеві виклики, утримуючи сесію БД.
- Для performance-аудиту застосовуй skill `web-performance`; відокремлюй виміряні факти від ризиків і припущень.
