# Локальні правила: безпека

## Секрети й доступ

- `.env` не потрапляє у відповіді, логи й документацію; до Git додається лише `.env.example` без секретів.
- `SECRET_KEY` не має безпечного дефолту в production. Авторизацію, роль і право на зміну даних завжди перевіряє сервер.
- Паролі зберігай і перевіряй через bcrypt; відкриті демонстраційні паролі можливі лише в ізольованому seed-скрипті.

## Введення і browser

- Валідуй API через Pydantic. Для SQL використовуй ORM або параметризовані запити.
- Не передавай токени, ролі чи бізнес-дозволи як єдине джерело істини з frontend; сервер виконує повторну перевірку.
- Не вставляй неперевірені дані через `innerHTML`; зовнішні посилання з `target="_blank"` захищай `rel="noopener noreferrer"`.
- Для файлів перевіряй MIME, розмір, ім’я та шлях; не довіряй клієнтському шляху.
