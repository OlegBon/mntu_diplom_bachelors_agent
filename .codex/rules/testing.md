# Локальні правила: тестування

## Поточний стан

Тестовий контур реалізовано. Backend використовує `pytest` з маркерами
`unit`, `api`, `integration` та ізольовану SQLite БД у пам'яті; він не
підключається до XAMPP і не запускає руйнівний seed. Frontend має Node/jsdom
тести й Playwright E2E з mock HTTP та тимчасовим BrowserSync. Команди й точні
межі наведені в `AGENTS.md`.

## Майбутня стратегія

- Після введення `pytest` поділяй перевірки на unit (калькулятор, ML), API та integration (із ізольованою тестовою БД).
- Фікстури володіють даними; зовнішні сервіси, час і випадковість мокуються або фіксуються.
- Пріоритет: auth, RBAC, IDC-розрахунки, CRUD і міграції.
- Для створення або рев’ю pytest-набору застосовуй skill `python-testing`.
