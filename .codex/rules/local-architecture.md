# Локальні правила: архітектура

## 1. Межі шарів

- `backend/main.py` містить FastAPI-маршрути, HTTP-залежності та коди відповідей; не розміщуй тут SQL або правила оцінювання діамантів.
- `backend/schemas.py` містить Pydantic-контракти запиту й відповіді. Не повертай ORM-модель без `response_model`.
- `backend/crud.py` відповідає за SQLAlchemy-запити та перетворення даних.
- `backend/calculator.py` містить детерміновані правила IDC; `backend/ml_service.py` — окрему логіку прогнозування. Не дублюй їх на frontend як джерело істини.
- `backend/models.py` описує моделі SQLAlchemy, а `backend/database.py` — з'єднання та сесії.

## 2. Потік даних і API

1. Frontend викликає API через `frontend/src/js/modules/api.js`.
2. Маршрут валідовує введення Pydantic-схемою й перевіряє auth/RBAC, коли доступ не публічний.
3. CRUD або доменний сервіс виконує потрібну операцію через передану SQLAlchemy-сесію.
4. Маршрут повертає явний API-контракт або контрольовану HTTP-помилку.

Не змінюй форму API, CORS, авторизацію чи потік даних без читання `docs/architecture.md` і пов'язаних frontend/backend файлів.

### Публічні та захищені маршрути

- Публічний маршрут не отримує додаткових прав лише тому, що frontend приховав кнопку.
- Для маршруту зміни даних спочатку перевіряй токен, роль і право на конкретний ресурс, а вже потім виконуй CRUD-операцію.
- CORS є browser-обмеженням, а не механізмом авторизації. Локальні origins і майбутні production-домени мають конфігуруватися окремо.

### Еволюція системи

- Не змішуй майбутній PostgreSQL/deployment-контур з поточним MariaDB-кодом через Git-гілки. Відмінності належать до конфігурації, драйвера та версіонованих міграцій.
- Не створюй новий шар або сервіс тільки за назвою патерну. Виділяй його, коли він прибирає реальне дублювання, відокремлює доменну логіку або полегшує тестування.

## 3. Клієнтський стан

- Стан конкретної сторінки зберігай поруч з її DOM-логікою; не створюй глобальний стан без потреби.
- JWT та ідентифікатор користувача зберігаються й очищуються тільки через модуль авторизації.
- Серверні дані не вважай актуальними лише через `localStorage`: повторно отримуй їх через API для критичних дій.
- Для асинхронних операцій завжди передбачай стани завантаження, успіху та помилки.
- Не зберігай похідні server-дані як єдину істину на клієнті; після зміни звіту або ринкових даних оновлюй відображення з API.
