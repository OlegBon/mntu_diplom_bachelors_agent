# Мета навички (Skill Objective)
Забезпечити безпечне й структуроване ознайомлення AI-агента з новою або незнайомою кодовою базою. Навичка гарантує, що агент розуміє інфраструктуру, залежності та скрипти проєкту до того, як почне генерувати або змінювати код.

# Умови активації (Triggers)
Активуй цю навичку, якщо запит користувача містить:
- «Вивчи проєкт» / «Ознайомся з проєктом»;
- «Проведи онбординг»;
- «Подивися, як тут усе влаштовано»;
- або якщо ти вперше відкриваєш директорію, структури якої не знаєш.

# Інструкції з виконання (Execution Steps)
Ти ЗОБОВ'ЯЗАНИЙ виконати такі кроки суворо за порядком, використовуючи доступні інструменти файлової системи й термінала.
## Крок 1: Аналіз команд керування (Command Discovery)
З'ясуй, як керується проєкт.
1. Використай інструмент `read_file`, щоб знайти основний файл конфігурації пакетів (наприклад, `package.json`, `Makefile` або `docker-compose.yml`).
2. Витягни й проаналізуй доступні скрипти запуску (наприклад, блок `"scripts"`).
3. Зафіксуй команди для встановлення залежностей, запуску сервера розробки (dev), збірки (build) і тестування.

## Крок 2: Аналіз стека та інструментів (Tooling Discovery)
Визнач технологічний стек проєкту.
1. Вивчи списки залежностей (`dependencies` і `devDependencies`).
2. Знайди основні конфігураційні файли в корені проєкту (наприклад, `tsconfig.json`, `.eslintrc`, `vite.config.ts`, `webpack.config.js`).
3. Зафіксуй використаний фреймворк, наявність TypeScript, інструменти лінтингу й збірки, а також ключові бібліотеки (наприклад, для керування станом або роботи з API).

## Крок 3: Архітектура та структура папок (Architecture Discovery)
Зрозумій, як організована кодова база.
1. Виклич інструмент `execute_command` у терміналі з командою `ls -la` або `tree -L 2 -I 'node_modules|.qit|dist'`, щоб отримати дерево директорій.
2. Перевір наявність папки `/docs`, файлів `README.md` або `ARCHITECTURE.md`. Якщо вони є — ОБОВ'ЯЗКОВО прочитай їх через `read_file`.
3. Зафіксуй розташування ключових шарів: де містяться вихідні файли backend (сервер, контролери), frontend (компоненти, сторінки) й статичні assets.

## Крок 4: Тестовий запуск (Dry Run)
Перевір працездатність проєкту в поточному стані.
1. Якщо папка `node_modules` відсутня, встанови залежності через термінал (на основі даних із кроку 1).
2. Запусти команду старту сервера для розробки АБО команду збірки проєкту.
3. Проаналізуй вивід термінала (`stdout`/`stderr`). Переконайся, що процес запускається без критичних помилок компіляції (наприклад, "Cannot find module" або помилок роутингу).

# Обмеження та правила (Constraints & Rules)
- **НЕ ВНОСЬ ЗМІНИ:** Навичка призначена винятково для читання та запуску. Заборонено модифікувати файли, виправляти архітектуру або оновлювати залежності.
- **ЗУПИНКА:** Щойно крок 4 успішно завершено (проєкт запустився/зібрався), негайно припини дії в терміналі й переходь до формування звіту.
- **ІЗОЛЯЦІЯ:** Якщо на кроці 4 виникає фатальна помилка, зупинися, опиши її у звіті й чекай на вказівки. НЕ намагайся виправити її самостійно на цьому етапі.

# Формат відповіді (Expected Output)
Після успішного виконання всіх чотирьох кроків надай користувачу структурований звіт у форматі Markdown:
1. **Команди:** короткий список основних команд для роботи з проєктом.
2. **Стек:** ключові технології та інструменти.
3. **Архітектура:** короткий опис структури директорій (1–2 абзаци).
4. **Статус запуску:** чи успішно пройшов тестовий запуск (додай останні 2–3 рядки успішного логу термінала).
5. Заверши відповідь фразою: _"Ознайомлення завершено. Проєкт готовий до роботи. Чекаю на подальші вказівки."_
