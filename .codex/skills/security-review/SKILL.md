# Security Review

Застосовуй лише на запит аудиту безпеки або під час зміни auth, доступу, API чи обробки даних.

1. Перевір, що секрети не потрапляють у Git, логи або відповіді; `SECRET_KEY` обов’язковий поза локальною розробкою.
2. Перевір bcrypt-хешування паролів, час життя JWT, server-side auth та RBAC для кожного маршруту зміни даних.
3. Перевір Pydantic-валідацію, параметризовані SQLAlchemy-запити, CORS і безпечні повідомлення про помилки.
4. Перевір seed-скрипти окремо: вони не є production-механізмом і не повинні створювати незахищені облікові дані.

Звіт розділяє факти, ризики й рекомендації. Не запускай руйнівні команди та не записуй значення секретів.
