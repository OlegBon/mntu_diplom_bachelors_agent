# Database Reviewer

## Коли застосовувати

Застосовуй для рев’ю SQLAlchemy-моделей, `crud.py`, SQL, індексів, seed, пагінації або планування перенесення даних. Для UI-змін, які не впливають на дані, ця навичка не потрібна.

## Контекст Diamant ID

- Поточна runtime-БД — MariaDB/XAMPP; ORM — SQLAlchemy 2.
- `diamond_oltp` містить користувачів і звіти, `diamond_market` — довідники оцінок та індекси; `diamond_analytics` поки лише запланований.
- Канонічні джерела схеми — `backend/models.py`, `backend/schemas.py`, `backend/crud.py` та `scripts/seed_db.py`. Фактичну БД не змінюй для рев’ю.

## Порядок рев’ю

1. Прочитай змінені моделі, CRUD-код, схеми й пов'язаний маршрут. За потреби звір із `docs/architecture.md` та seed.
2. Перевір первинні й зовнішні ключі, `NOT NULL`, унікальність, типи, значення за замовчуванням і поведінку зв'язків.
3. Зістав поля фільтрації, `JOIN`, сортування та пагінації з індексами. Для великих списків познач ризик великого `OFFSET` або N+1.
4. Перевір точність грошей через `DECIMAL`, узгодженість дат/часу й те, що введення не конкатенується в SQL.
5. Для гарячого запиту запропонуй безпечний план вимірювання. Не запускай `EXPLAIN ANALYZE`, SQL, seed або міграцію без явного дозволу користувача.
6. Якщо задача стосується PostgreSQL, окремо познач різницю діалектів та потребу в Alembic; не припускай, що міграція вже існує.

## Формат результату

Подай висновки за пріоритетами `Критично`, `Важливо`, `Рекомендація`. Для кожного зазнач файл або сутність, спостереження, ризик, доказ і конкретну дію. Якщо проблем не знайдено, переліч виконані перевірки й неперевірені припущення.
