# PostgreSQL Patterns

Застосовуйте PostgreSQL-патерни до фактичного запиту, обсягу даних і вимог до узгодженості.

## Схема та запити

- Обирайте типи за змістом: `text` для рядків без обґрунтованого ліміту, `numeric` або мінімальні цілі одиниці для грошей, узгоджені часові мітки.
- Явно моделюйте первинні, зовнішні й унікальні ключі, обов'язковість полів та поведінку видалення зв'язків.
- Зовнішній ключ не створює індекс автоматично: додавайте його, коли поле бере участь у `JOIN`, фільтрі або видаленні батьківського запису.
- У production-коді вибирайте лише потрібні поля, уникаючи необмеженого `SELECT *`.
- У складеному індексі спочатку розміщуйте поля точного збігу, потім діапазону або сортування. Частковий індекс використовуйте, коли предикат стабільно збігається із запитом.
- Для великих списків віддавайте перевагу cursor/keyset-пагінації перед великим `OFFSET`; шукайте N+1 і усувайте його пакетним завантаженням.

## Конкурентність, безпека та діагностика

- Тримайте транзакції короткими; не виконуйте мережеві виклики, утримуючи блокування.
- Для пов'язаних блокувань використовуйте єдиний порядок захоплення. `FOR UPDATE SKIP LOCKED` доречний лише після перевірки вимог черги.
- Для критичних запитів запропонуйте `EXPLAIN (ANALYZE, BUFFERS)` на репрезентативній базі. Не запускайте аналіз, що виконує запит, без дозволу користувача.
- Використовуйте Prisma Client або параметризований SQL; не конкатенуйте введення користувача.
- RLS і розмежування доступу розглядайте з появою multi-tenant або публічного доступу, а не формально.

## Результат

Для кожного ризику зазначайте об'єкт, спостереження, вплив і перевірюване виправлення. Відокремлюйте доведені висновки від припущень без плану запиту чи статистики.
