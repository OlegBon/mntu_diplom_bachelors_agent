# Frontend Patterns

## Коли застосовувати

Застосовуй під час написання, рев’ю або рефакторингу Pug-шаблонів, SCSS, JavaScript-модулів, Gulp-конфігурації та інтеграції frontend з FastAPI.

## Структура

- Джерела — лише `frontend/src/pug`, `frontend/src/scss`, `frontend/src/js`, `frontend/src/img`.
- `frontend/dist` є результатом збірки: не редагуй його вручну.
- API-виклики зосереджуй у `src/js/modules/api.js`; перевірку та очищення сесії — у `src/js/modules/auth.js`.
- Не додавай framework, bundler або пакет лише для невеликої локальної задачі без окремого обґрунтування.

## Pug і доступність

- Використовуй семантичні елементи та один зрозумілий `label` для кожного поля форми.
- Для полів входу й персональних даних вказуй коректний `autocomplete`.
- Повідомлення про помилку мають бути доступними й не покладатися лише на колір.
- Для зовнішнього посилання з `target="_blank"` додавай `rel="noopener noreferrer"`.

## SCSS і JavaScript

- Використовуй токени з `_variables.scss` і правила `DESIGN.md`; не дублюй магічні кольори, відступи та breakpoints.
- Розділяй отримання DOM-елементів, обробку подій, рендеринг і мережеві виклики. Обробляй помилки `fetch` та не показуй технічні деталі користувачу.
- Не довіряй даним із DOM або `localStorage` як авторитетним для доступу чи розрахунків: сервер перевіряє auth/RBAC і доменні правила.
- Не додавай inline-обробники подій та не використовуй `innerHTML` з неперевіреними даними.

## Перевірка

Після змін запускай `cmd /c "cd frontend && npm run build"`. Для UI-зміни перевір відрендерену сторінку й цільовий сценарій у браузері; результат зафіксуй у `docs/progress.md`.
